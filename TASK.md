# Тестовое задание: сервис анализа игр с Metacritic

## Исходное ТЗ (от работодателя)

Реализовать сервис, который 1 раз в час заходит на Metacritic в раздел Games, берёт новые 20 игр, которые сегодня не обрабатывал, и добавляет информацию о них в свою базу или обновляет её, если игра уже есть.

Выборка игр:
1. Первые 20 игр берём со страницы Games https://www.metacritic.com/game/, раздел New Releases.
2. При последующих обработках берём игры из раздела SEE ALL (сортировка «Новые»): https://www.metacritic.com/browse/game/all/all/all-time/new/. За каждый заход обрабатываем очередную страницу.
3. Каждый новый день начинаем заново: сначала игры из пункта 1, затем из 2.

Информация по игре: название, обложка, платформы с Metascore и Userscore (платформ может быть много), разработчик, описание, ссылка на видео. Плюс короткое резюме по отзывам: что игрокам нравится и что нет, отдельно для критиков и для пользователей; может обновляться при повторных обходах.

Веб-интерфейс: список игр (кратко), карточка игры (полностью), фильтр по платформам, поиск по названию, сортировка по рейтингу. Для каждой игры похожие игры из базы, клик открывает их карточку.

Дополнительно 1: для каждой игры найти самый популярный летсплей на YouTube, перевести рассказ блогера в текст, сделать заключение и добавить к игре со ссылкой на ролик.

Дополнительно 2: мониторинг работы сервиса в реальном времени (статусы воркеров, количество обработанных записей и т.п.) и кнопка принудительного запуска.

Результат: ссылка на репозиторий, ссылка на работающий сервис, вся переписка с нейросетью (raw JSONL).

## Правила этой сессии

- Переписка этой сессии пойдёт работодателю целиком. Работаем только над этим заданием.
- Никаких секретов в чате и в коде: ключи только через переменные окружения на сервере (`.env` в `.gitignore`, в репозитории `.env.example`). Не открывать и не выводить файлы с ключами.
- Код и конфиги на английском, README на русском (можно продублировать на английском).

## Шаг 0. Кликабельный прототип (GitHub Pages)

Один HTML-файл без сборки, данные — 15-20 реальных свежих игр (можно заполнить вручную или моками в духе Metacritic), выложить на GitHub Pages. Десктоп и мобильная версия (проверить скриншотами на 1440 и 390 px). Всё кликабельно:
- список игр: обложки, платформы с оценками, фильтр по платформам, поиск, сортировка;
- карточка игры: все поля из ТЗ, резюме критиков и игроков, видео, похожие игры с объяснением «почему похожи»;
- вау-фичи (ниже) в виде работающих макетов;
- экран мониторинга: схема конвейера с подсветкой этапов, статусы воркеров, счётчики, лог, кнопка «Запустить сейчас».
Прототип потом становится дизайном настоящего фронтенда.

## Вау-фичи (по приоритету)

1. «Критики против игроков»: радар по аспектам (геймплей, графика, сюжет, оптимизация, цена, мультиплеер) для критиков и игроков, бейдж расхождения, при наведении цитаты из отзывов, на которых основан вывод.
2. Карта игр: интерактивная 2D-карта по эмбеддингам, похожие игры рядом, кластеры подписаны, клик открывает карточку.
3. Мониторинг-конвейер: этапы сбор → разбор → резюме → эмбеддинги → похожие подсвечиваются в реальном времени, стоимость в токенах и долларах на игру.
4. Летсплей с таймкодами: заключение и ключевые моменты со ссылками на секунду ролика.
5. Чат с базой: вопрос обычным языком, агент ищет по базе и отвечает со ссылками на карточки.
6. Инсайты по жанру: что игроки чаще хвалят и за что ругают игры жанра за период.

## Архитектура (предложение)

- Python, FastAPI, PostgreSQL + pgvector, планировщик раз в час (APScheduler) и фоновые воркеры; состояние обхода «сегодняшних» игр и курсор страницы SEE ALL в БД.
- Сбор: сначала проверить, какие JSON-запросы делает сам сайт Metacritic (DevTools); если данные отдаёт внутренний API, использовать его, иначе Playwright. Вежливая частота, ретраи, идемпотентный upsert.
- LLM через OpenAI-совместимый API (модель в env). Резюме и аспекты — structured output, каждое утверждение с опорой на цитату из отзыва.
- Похожие: эмбеддинги описания, жанров и аспектов + ближайшие соседи в pgvector; объяснение общих признаков.
- Летсплеи: YouTube Data API (поиск, сортировка по просмотрам) → аудио yt-dlp → Whisper → заключение с таймкодами.
- Мониторинг: события воркеров в БД + SSE на фронт; кнопка ручного запуска с защитой от двойного старта.
- Фронтенд по дизайну прототипа. Docker Compose, деплой на сервер за Caddy (HTTPS), CI с тестами.
- README: схема архитектуры, решения и компромиссы, как запустить, демо-видео на 2 минуты.
