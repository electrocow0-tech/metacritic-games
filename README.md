# Scorecast: анализ свежих игр Metacritic

Сервис раз в час забирает с Metacritic очередные 20 игр, которые сегодня ещё не обрабатывал, сохраняет их в базу (или обновляет уже известные), делает резюме отзывов отдельно для критиков и игроков, находит похожие игры и показывает всё в веб-интерфейсе с мониторингом конвейера.

- Сервис: https://games.1-lab.online
- Мониторинг и ручной запуск: https://games.1-lab.online/#/monitor
- Кликабельный прототип (дизайн и демо дополнительных идей): https://electrocow0-tech.github.io/metacritic-games/
- Постановка задачи, декомпозиция и план: [TASK.md](TASK.md)

## По ТЗ

| Требование | Реализация |
|---|---|
| Раз в час 20 новых игр, которые сегодня не обрабатывались | APScheduler в воркере (`app/worker.py`), обработанные за день игры в таблице `crawl_processed` |
| Первый заход дня: New Releases со страницы Games | `crawler.select_batch`: slug'и раздела New Releases с `/game/`; если их меньше 20, добор из SEE ALL |
| Следующие заходы: SEE ALL, сортировка «новые», очередная страница | курсор `crawl_days.see_all_page`; страница считается пройденной, когда с неё забраны все необработанные игры |
| Каждый новый день заново | состояние хранится по дате в часовом поясе `TZ`, новый день означает новую строку `crawl_days` |
| Добавить игру или обновить, если она уже есть | идемпотентный upsert по `slug`, отзывы по хешу автора, даты и текста |
| Название, обложка, платформы с Metascore и Userscore, разработчик, описание, ссылка на видео | таблицы `games` и `game_platforms`; отсутствующая оценка (tbd) хранится как `NULL` и показывается «нет оценки», в средних и сортировке не участвует |
| Резюме: что нравится и что нет, отдельно критики и игроки, обновляется при повторных обходах | `app/summarizer.py`, таблица `summaries`; пересчёт, когда изменился набор отзывов (`reviews_hash`) |
| Веб: список кратко, карточка полностью, фильтр по платформам, поиск по названию, сортировка по рейтингу | `frontend/index.html` (дизайн из прототипа), `GET /api/games?q=&platform=&sort=`, `GET /api/games/{slug}` |
| Похожие игры из базы, клик открывает их карточку | `app/similar.py`, таблица `similar_games` с объяснением, почему игры похожи |

## Дополнительно

## Ограничения

- **Заключения по летсплеям есть не у всех игр.** Заключение строится из автосубтитров YouTube. YouTube блокирует их загрузку с IP датацентров, а один residential-выход блокируется примерно после 20 роликов подряд. Поэтому сейчас заключения есть у части игр, а у остальных сохраняется ссылка на самый популярный ролик.
- **Как закрыть это полностью, если понадобится.** Есть два пути: пул ротируемых residential-прокси (адрес задаётся в `YOUTUBE_PROXY`, при `IpBlocked` нужно переключаться на другой выход) или сторонний API расшифровок (Supadata и аналоги, бесплатно от 100 запросов в месяц). Код к этому готов: интервал между запросами (`YOUTUBE_INTERVAL`), лимит роликов в час (`YOUTUBE_HOURLY_LIMIT`) и пауза при блокировке (`YOUTUBE_BLOCK_PAUSE_MIN`) настраиваются в env. Без прокси или без автосубтитров у ролика сохраняется ссылка без заключения.
- **На обязательную часть и мониторинг это ограничение не влияет.**
- **У большинства свежих игр пока нет отзывов.** Лента SEE ALL «новые» состоит из релизов последних дней, и у большинства таких игр на Metacritic ещё нет ни рецензий, ни отзывов игроков. Для них резюме не строится, в мониторинге это видно как «мало для резюме». Когда отзывы появятся, они попадут в базу при повторном обходе игры или при досчёте.

## Архитектура

```
              ┌──────────────── games-worker ────────────────┐
 Metacritic   │ APScheduler (раз в час) ──┐                   │
 JSON API ───►│ очередь runs в БД ◄───────┴── POST /api/runs  │
 YouTube ────►│ collector → llm-1, llm-2 → matcher → letsplay │
              └────────────────────┬──────────────────────────┘
                                   │ upsert, события, статусы воркеров
                              ┌────▼─────┐
                              │ Postgres │
                              └────┬─────┘
                                   │
 Caddy (HTTPS) ──► games-web: FastAPI /api/*, SSE, frontend/index.html
```

- **Сбор** (`app/metacritic.py`). Сайт Metacritic сам берёт данные из внутреннего JSON API `backend.metacritic.com`, защиты от ботов там нет, поэтому браузер (Playwright) не нужен:
  - `finder/metacritic/web?sortBy=-releaseDate…`: лента SEE ALL;
  - `composer/metacritic/pages/games/{slug}/web`: вся страница игры одним ответом;
  - `reviews/metacritic/user/games/{slug}/platform/{platform}/stats/web`: Userscore по платформе;
  - `reviews/metacritic/{critic|user}/games/{slug}/web`: отзывы с пагинацией.

  Раздел New Releases есть только в HTML главной `/game/`. Запросы идут с паузой 1 секунда, на 429 и 5xx повторяются с экспоненциальной паузой.
- **Конвейер** (`app/pipeline.py`). Воркеры связаны очередями. Сборщик работает в один поток, чтобы не нагружать сайт, LLM-воркеров два. Ошибка одной игры пишется в лог и не роняет заход. После перезапуска процесса незавершённый запуск помечается упавшим, чтобы очередь не блокировалась.
- **Резюме** (`app/summarizer.py`). Работают через любой OpenAI-совместимый API (`LLM_BASE_URL`, `LLM_MODEL`), ответ в JSON. Тезисы с цитатой, которой нет в отзывах, отбрасываются. Без `LLM_API_KEY` конвейер работает дальше, а этап резюме помечается пропущенным.
- **Похожие игры** (`app/similar.py`). Косинус по признакам: жанры, разработчик и издатель, платформы, TF-IDF описания. Если задан `EMBEDDING_MODEL`, добавляется семантический эмбеддинг. Векторная БД не нужна: для сотен и тысяч игр полный пересчёт занимает доли секунды. После каждого захода похожие пересчитываются по всей базе, потому что новые игры могут стать соседями старых.
- **Летсплеи** (`app/letsplay.py`). Ролик ищется по точной фразе «"<название>" gameplay». Принимаются только ролики, в названии которых есть все значимые слова названия игры, из них выбирается ролик длиннее 5 минут с максимумом просмотров. Субтитры берутся через `YOUTUBE_PROXY`. Если субтитров нет, это не ошибка: сохраняется ссылка без заключения.
- **Мониторинг.** Каждый шаг пишет событие в `run_events`, воркеры шлют heartbeat в `workers`. Фронтенд получает состояние и лог через SSE. Защита от двойного старта: уникальный частичный индекс `runs_single_active` разрешает только один запуск в статусе `queued` или `running`, повторный `POST /api/runs` получает 409.

### API

| Метод | Назначение |
|---|---|
| `GET /api/meta` | всего игр, дата последнего сбора, платформы с количеством |
| `GET /api/games?q=&platform=&sort=meta\|user\|date\|div\|title&limit=&offset=` | список с фильтром, поиском и сортировкой |
| `GET /api/games/{slug}` | карточка: платформы, резюме, похожие, летсплей |
| `GET /api/monitor/state`, `GET /api/monitor/events`, `GET /api/monitor/stream` | состояние конвейера, лог, SSE |
| `POST /api/runs` | ручной запуск (202 или 409, если запуск уже идёт) |

## Запуск

Сервер: Docker Compose, Caddy проксирует домен на `games-web:8000` через внешнюю сеть `health-bot_default`, порты наружу не публикуются.

```bash
cd /opt/metacritic-games        # здесь лежит .env (шаблон: .env.example)
git pull
docker compose up -d --build
docker compose logs -f games-worker
```

Локально (PostgreSQL 16+, Python 3.12):

```bash
uv venv --python 3.12 && uv pip install -r pyproject.toml pytest
cp .env.example .env            # DATABASE_URL на локальную базу, ключ LLM по желанию
uvicorn app.api:app --port 8000 # API и фронтенд
python -m app.worker            # планировщик и конвейер; на пустой базе первый заход стартует сразу
pytest                          # правила обхода, проверка цитат, релевантность роликов
```

Разовый досчёт. Игры без отзывов перезапрашиваются с Metacritic, затем строятся недостающие резюме и эмбеддинги, а ссылки на летсплеи ищутся заново или перепроверяются. Досчёт идемпотентен и виден в мониторинге как обычный запуск:

```bash
cd /opt/metacritic-games && docker compose exec -d games-worker python -m app.backfill
# варианты: --skip-letsplay, --only-letsplay
```

## Решения и компромиссы

- **Внутренний API вместо парсинга HTML.** Так быстрее и стабильнее, но API недокументирован и может измениться. Все вызовы собраны в одном модуле `app/metacritic.py`.
- **«Очередная страница».** На странице SEE ALL 24 игры, а за заход нужно 20, поэтому курсор сдвигается, когда страница исчерпана. Лента сортируется по дате, и в течение дня в неё добавляются новые игры. Повторов при этом нет: всё, что уже обработано сегодня, отсекается.
- **Обложка.** Храним ссылку на изображение Metacritic, сами картинки не копируем. Если картинка недоступна, фронтенд рисует плейсхолдер.
- **Userscore и число отзывов.** В счётчик отзывов игроков на Metacritic входят и оценки без текста, а резюме строится только по текстовым отзывам. Поэтому на карточке пишем «проанализировано N из M».
- **Без векторной БД и без ORM.** Для сотен и тысяч игр хватает обычного PostgreSQL, SQL через psycopg и косинуса в numpy. Меньше зависимостей, меньше точек отказа.

## Как шла разработка

Разработка шла вместе с AI-ассистентом: исследование API Metacritic, код, разметка отзывов для прототипа, вёрстка. По просьбе работодателя полные логи сессий (raw JSONL) приложены к результату. Ключи и секреты не попадают ни в репозиторий, ни в переписку: на сервере они задаются через переменные окружения (`.env` в `.gitignore`, в репозитории только `.env.example`).
