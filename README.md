# Scorecast: анализ свежих игр Metacritic

Сервис раз в час забирает с Metacritic очередные 20 игр, которые сегодня ещё не обрабатывал, сохраняет их в базу (или обновляет), делает резюме отзывов критиков и игроков, находит похожие игры и показывает всё это в веб-интерфейсе с мониторингом конвейера.

- Сервис: https://games.1-lab.online
- Прототип (дизайн и демо дополнительных идей): https://electrocow0-tech.github.io/metacritic-games/
- Постановка задачи, декомпозиция и план: [TASK.md](TASK.md)

## Что сделано по ТЗ

| Требование | Реализация |
|---|---|
| Раз в час 20 новых игр, которые сегодня не обрабатывались | APScheduler в воркере (`app/worker.py`), обработанные за день игры в таблице `crawl_processed` |
| Первый заход дня: New Releases со страницы Games | `crawler.select_batch`: slug'и раздела New Releases с `/game/`; если их меньше 20, добор из SEE ALL |
| Следующие заходы: SEE ALL, сортировка «новые», очередная страница | курсор страницы `crawl_days.see_all_page`, страница пройдена, когда с неё забраны все необработанные игры |
| Каждый новый день заново | состояние хранится по дате (часовой пояс `TZ`), новый день = новая строка `crawl_days` |
| Добавить или обновить игру | идемпотентный upsert по `slug`, отзывы по хешу автора, даты и текста |
| Название, обложка, платформы с Metascore и Userscore, разработчик, описание, видео | таблицы `games` и `game_platforms`; отсутствующая оценка (tbd) хранится как `NULL` и показывается «нет оценки» |
| Резюме: что нравится и что нет, отдельно критики и игроки, обновляется при повторных обходах | `app/summarizer.py`, таблица `summaries`; пересчёт, только если изменился набор отзывов (`reviews_hash`) |
| Веб: список, карточка, фильтр по платформам, поиск, сортировка по рейтингу | `frontend/index.html` (дизайн из прототипа) + `GET /api/games?q=&platform=&sort=` |
| Похожие игры из базы, клик открывает карточку | `app/similar.py`, таблица `similar_games` с объяснением, почему игры похожи |

## Дополнительно

| Пункт | Реализация |
|---|---|
| Доп. 1: самый популярный летсплей, текст рассказа, заключение со ссылкой | `app/letsplay.py`: поиск через `yt-dlp` (`ytsearch20`, ролик про эту игру длиннее 5 минут с максимумом просмотров), автосубтитры через `youtube-transcript-api`, заключение и ключевые моменты с таймкодами через LLM. Автосубтитры YouTube отдаёт только на residential IP, поэтому на сервере они идут через прокси `YOUTUBE_PROXY` |
| Доп. 2: мониторинг в реальном времени и принудительный запуск | события воркеров в `run_events`, статусы в `workers`, SSE `GET /api/monitor/stream`, кнопка `POST /api/runs` с защитой от двойного старта |
| Проверка цитат в резюме | каждый тезис опирается на дословную цитату из отзыва; тезисы с цитатой, которой нет в отзывах, отбрасываются кодом |
| Прототип с вау-идеями (только демо, в сервис не переносились) | радар «критики против игроков», карта игр, чат с базой, инсайты: `docs/index.html` |

## Архитектура

```
              ┌────────────── games-worker ──────────────┐
 Metacritic   │ APScheduler (раз в час) ─┐               │
 JSON API ───►│ очередь runs (БД) ◄──────┴─ POST /api/runs│
 YouTube      │                                          │
 (yt-dlp) ───►│ collector → llm-1, llm-2 → matcher → letsplay
              └───────────────┬──────────────────────────┘
                              │ upsert, события, статусы
                         ┌────▼─────┐
                         │ Postgres │
                         └────┬─────┘
                              │
 Caddy (HTTPS) ──► games-web: FastAPI /api/*, SSE, frontend/index.html
```

- **Сбор.** Сайт Metacritic сам берёт данные из внутреннего JSON API `backend.metacritic.com`, защиты от ботов там нет, поэтому браузер (Playwright) не нужен:
  - `finder/metacritic/web?sortBy=-releaseDate…`: лента SEE ALL;
  - `composer/metacritic/pages/games/{slug}/web`: вся страница игры одним ответом;
  - `reviews/metacritic/user/games/{slug}/platform/{platform}/stats/web`: Userscore по платформе;
  - `reviews/metacritic/{critic|user}/games/{slug}/web`: отзывы с пагинацией.

  Раздел New Releases есть только в HTML главной `/game/`. Запросы идут вежливо: пауза 1 секунда, повторы с экспоненциальной паузой на 429 и 5xx.
- **Конвейер** (`app/pipeline.py`). Сборщик работает в один поток, чтобы не нагружать сайт. LLM-воркеров два. Ошибка одной игры логируется и не роняет заход.
- **Резюме.** Работают через любой OpenAI-совместимый API (`LLM_BASE_URL`, `LLM_MODEL`), ответ в JSON. Без `LLM_API_KEY` конвейер работает дальше, а этап резюме честно помечается пропущенным.
- **Похожие игры.** Косинус по признакам: жанры, разработчик и издатель, платформы, TF-IDF описания. Если задан `EMBEDDING_MODEL`, добавляется семантический эмбеддинг. Векторная БД не нужна: для сотен и тысяч игр полный пересчёт занимает доли секунды. После каждого захода похожие пересчитываются для всей базы, потому что новые игры могут стать соседями старых.
- **Защита от двойного старта.** Уникальный частичный индекс `runs_single_active`: одновременно может быть только один запуск в статусе `queued` или `running`. Повторный `POST /api/runs` получает 409.

## Запуск

Сервер (Docker Compose, Caddy уже проксирует домен на `games-web:8000` через внешнюю сеть `health-bot_default`):

```bash
cd /opt/metacritic-games        # здесь лежит .env (шаблон: .env.example)
git pull
docker compose up -d --build
docker compose logs -f games-worker
```

Локально (PostgreSQL 16+, Python 3.12):

```bash
uv venv --python 3.12 && uv pip install -r pyproject.toml pytest
cp .env.example .env            # DATABASE_URL на локальную базу, ключ LLM по желанию
uvicorn app.api:app --port 8000 # API + фронтенд
python -m app.worker            # планировщик и конвейер; на пустой базе первый заход стартует сразу
pytest                          # правила обхода и проверка цитат
```

Разовый досчёт по всей базе. Игры без отзывов перезапрашиваются с Metacritic (отзывы появляются через дни после релиза). Затем строятся недостающие резюме и эмбеддинги, а ссылки на летсплеи ищутся заново или перепроверяются на релевантность. Досчёт идемпотентен и виден в мониторинге как обычный запуск:

```bash
cd /opt/metacritic-games && docker compose exec games-worker python -m app.backfill
# только летсплеи: заключения для сохранённых ссылок и поиск недостающих (в фоне)
cd /opt/metacritic-games && docker compose exec -d games-worker python -m app.backfill --only-letsplay
```

## Решения и компромиссы

- **Внутренний API вместо парсинга HTML.** Так быстрее и стабильнее, но API недокументирован и может измениться. Все вызовы собраны в `app/metacritic.py`.
- **Как понимать «очередная страница».** На странице SEE ALL 24 игры, а за заход нужно 20. Поэтому курсор сдвигается, только когда страница исчерпана. Лента сортируется по дате, и в течение дня в неё добавляются новые игры. Повторов при этом нет: всё, что уже обработано сегодня, отсекается.
- **Обложка.** Храним ссылку на изображение Metacritic, сами картинки не копируем. Если картинка недоступна, фронтенд рисует плейсхолдер.
- **Летсплей.** «Самый популярный» понимаем как ролик длиннее 5 минут с максимумом просмотров по запросу «<название> gameplay». Часто это обзор крупного канала, а не прохождение. Субтитры берутся автоматические, поэтому в тексте возможны ошибки распознавания.
- **Субтитры YouTube требуют residential IP.** С IP датацентра YouTube отвечает на запрос субтитров 429 или просит подтвердить, что это не бот. PO token этого не исправляет, мы проверили. Поэтому субтитры запрашиваются через прокси с residential-выходом: адрес задаётся в `YOUTUBE_PROXY`, например `socks5h://host.docker.internal:1080` (контейнер воркера видит хост через `extra_hosts`). Без прокси ссылка на самый популярный ролик всё равно сохраняется, а заключение пропускается. Отсутствие автосубтитров у ролика тоже не считается ошибкой: в этом случае сохраняется только ссылка. При ответе 429 запросы субтитров встают на паузу на 30 минут. Темп обращений к YouTube: не больше 1 запроса в секунду.
- **Релевантность ролика.** Поиск идёт точной фразой, и ролик принимается, только если в его названии есть все значимые слова названия игры. Иначе для малоизвестных игр выбиралось чужое популярное видео.

## Как шла разработка

Разработка шла вместе с AI-ассистентом: исследование API Metacritic, код, разметка отзывов для прототипа, вёрстка. По просьбе работодателя полные логи сессий (raw JSONL) приложены к результату. Ключи и секреты не попадают ни в репозиторий, ни в переписку: на сервере они задаются через переменные окружения (`.env` в `.gitignore`, в репозитории только `.env.example`).
